# FiveM (Cfx.re) resources that change or measure GTA V vehicle physics

Scope: FiveM only (single-player ScriptHookV mods are covered elsewhere). Method: GitHub repo/code search (via `gh search`), raw source reads from raw.githubusercontent.com, Cfx.re forum release threads (via Firecrawl), and the primary native-doc sources (`citizenfx/fivem/ext/native-decls` for CFX-added natives, `citizenfx/natives` for game natives, `alloc8or/gta5-nativedb-data` for NativeDB). Licences are those GitHub reports for the repo ("none" = no licence file detected, i.e. all rights reserved by default). Star counts/dates were read on 2026-11-12.

Wheel-index convention used below: the CFX-added per-wheel natives (`GET_VEHICLE_WHEEL_*`) take an index from 0 to `GET_VEHICLE_NUMBER_OF_WHEELS-1` ([GetVehicleWheelSpeed.md](https://github.com/citizenfx/fivem/blob/master/ext/native-decls/GetVehicleWheelSpeed.md)); some game natives use a different, fixed tyre enumeration (0 wheel_lf, 1 wheel_rf, 2 wheel_lm1, 3 wheel_rm1, 4 wheel_lr, 5 wheel_rr) ([NativeDB SET_TYRE_WEAR_RATE](https://github.com/alloc8or/gta5-nativedb-data/blob/master/natives.json)).

## Q1 — Which FiveM drift scripts exist, and which natives / handling changes do they use to make cars drift?

### Takeaway
Almost every free FiveM "drift mode" is the same 5-line trick: while a key (usually Shift) is held below a speed cap, call the game native `SetVehicleReduceGrip(vehicle, true)` every tick; vMenu ships the identical toggle. More "serious" drift setups instead change handling (`fDriveBiasFront = 0` for RWD, lowered traction curves, torque boosts when sideways) or override surface grip tables server-wide, and drift *scoring* scripts measure the slip angle from `GetEntityVelocity` vs `GetEntityRotation`.

### Cited Findings

**Drift toggles (grip reduction)**
- **vMenu "Drift Mode" (Tom Grobbe, `TomGrobbe/vMenu`, 426★, GitHub licence "other" = custom non-SPDX licence)**: when `KbDriftMode` is on and the player holds Sprint (Shift, keyboard) or Jump (gamepad) it calls `SetVehicleReduceGrip(veh.Handle, true)` and calls it with `false` on release — [vMenu FunctionsController.cs](https://github.com/TomGrobbe/vMenu/blob/master/vMenu/FunctionsController.cs) (lines ~995-1015).
- **StockholmCityRP `drift_mode` (scrp-scripts, 36★, no licence)**: toggle with numpad-9; while in driver seat and speed ≤ `drift_speed_limit = 100.0` km/h (`GetEntitySpeed*3.6`), holding Left Shift → `SetVehicleReduceGrip(vehicle, true)`, else `false`, polled every 10 ms — [drift_mode-client.lua](https://github.com/StockholmCityRP/scrp-scripts/blob/master/client/drift_mode-client.lua).
- **mri_Qbox drift module (mri-Qbox-Brasil)**: same pattern, 500 ms poll, cap `cfg.speed or 80` km/h, `SetVehicleReduceGrip(vehicle, IsControlPressed(0, 21))` — [modules/drift/client.lua](https://github.com/mri-Qbox-Brasil/mri_Qbox/blob/main/resources/modules/drift/client.lua).
- GitHub code search also returns several other copies of the same `SetVehicleReduceGrip` drift toggle (e.g. `Crazioz/CzBase_V1 simpledrift/drift.lua`, `Knoees/knoes-smallresources client/drift.lua`, `naufalmulyarizki/naufal-snippets-fivem Drift/client/drifthold.lua`, `HoppeDevz/bclrp hpp_garages/drift.lua`) — [GitHub code search "SetVehicleReduceGrip" language:lua](https://github.com/search?q=SetVehicleReduceGrip+language%3ALua&type=code).
- Other small open repos: `ethanfs20/fivem_driftmode` (MIT, "driftmode") and `envSCRIPTS/dd5m_drifttuner` ("Ox_lib/QBox FiveM drift tuner with db sync. Tuner status stored to vehicles table") — [github.com/ethanfs20/fivem_driftmode](https://github.com/ethanfs20/fivem_driftmode), [github.com/envSCRIPTS/dd5m_drifttuner](https://github.com/envSCRIPTS/dd5m_drifttuner) (contents not inspected).

**Handling-based / paid drift systems**
- **Quags Drift (QuagsGarcia; paid $5, escrow-encrypted, 2022)**: "adds power to your car when you are sideways" and stalls the engine in PIT scenarios; requires RWD (`fDriveBiasFront` = 0.0 in handling.meta); natives quoted in the thread: `SetVehicleReduceGrip`, `SetVehicleReduceTraction(veh, 0.5)` and `SetVehicleEngineTorqueMultiplier(vehicle, factor)`; advertised as "More Realistic Than vMenu Drift" — [Cfx.re thread](https://forum.cfx.re/t/quags-drift-engine-stall-and-drift-script/4824814).
- **RS Tuner Chip (RealitySucksRP)**: "A vehicle-bound FiveM drift controller with eight stock-relative handling profiles" (i.e. handling multipliers relative to stock), distributed via GitHub releases + Tebex store — [README](https://github.com/RealitySucksRP/RealitySucks-TunerChip/blob/main/README.md) (GitHub licence "other"; source not inspected).
- **drift-system (EnderDevelopment)**: ESX drift points where "Gravity levels will adjust based on the drift points" (i.e. `SetVehicleGravityAmount`-style tuning); README states it was AI-generated by the EnderDevelopment platform — [README](https://github.com/EnderDevelopment/drift-system/blob/main/README.md). Low trust.
- **Fivem_Drift_Surfaces (DriftJohnson)**: a data-only resource that re-streams the surface grip / tyre-heat "bell curve" tables (vanilla values, plus a "30percentless" example reducing grip on all surfaces by 30%) to stop client-side grip exploits on drift servers — [README](https://github.com/DriftJohnson/Fivem_Drift_Surfaces/blob/master/README.md).
- **DriftV (Rubylium; 49★, no licence)**: a full drift *gamemode* base (OneSync, oxmysql, separate `drift-vehicles`, `hologramspeed`, `speedometer`, `fh4map` resources) — [README](https://github.com/Rubylium/DriftV/blob/main/README.md). (Drift-physics code itself not inspected.)

**Drift scoring / measurement**
- **FiveM-DriftCounter (Blumlaut; MIT, 12★)**: computes the drift angle each tick from velocity vs heading: `vx,vy = GetEntityVelocity`, `rz = GetEntityRotation(veh,0).z`, `cosX = (-sin(rz)*vx + cos(rz)*vy)/|v|`; returns 0 if speed < 30 km/h, gear == 0, `cosX > 0.966` (< ~15°) or `cosX < 0` (reversing); else `deg(acos(cosX))*0.5`; only scores when `IsVehicleOnAllWheels` — [driftcounter_c.lua](https://github.com/Blumlaut/FiveM-DriftCounter/blob/master/driftcounter_c.lua).
- `ZeroDream-CN/dpoint` (GPL-3.0, "FiveM Drift Point script") and `GitScorz/scorz-drifting` exist as further scoring scripts — [GitHub search "fivem drift"](https://github.com/search?q=fivem+drift&type=repositories) (not inspected).

**Relevant drift natives (docs)**
- `SET_VEHICLE_REDUCE_GRIP(Vehicle, BOOL)` (0x222FF6A823D122E2): "Reduces grip significantly so it's hard to go anywhere." — [citizenfx/natives SetVehicleReduceGrip.md](https://github.com/citizenfx/natives/blob/master/VEHICLE/SetVehicleReduceGrip.md).
- `SET_VEHICLE_REDUCE_GRIP_LEVEL(Vehicle, int val)` (0x6DEE944E1EE90CFB): "val is 0-3. Often used in conjunction with: SET_VEHICLE_REDUCE_GRIP" — [NativeDB data](https://github.com/alloc8or/gta5-nativedb-data/blob/master/natives.json).
- Game also exposes `SET_DRIFT_TYRES(Vehicle, BOOL)` / `GET_DRIFT_TYRES_SET` (0x5AC79C98C5C17F05 / 0x2F5A72430E78C8D3) and `_SET_DRIFT_SLIP_ANGLE_LIMITS(vehicle, durationScalar, amplitudeScalar, slipAngleLimit)` ("First two floats relate to rumble, the last is a threshold") — [NativeDB data](https://github.com/alloc8or/gta5-nativedb-data/blob/master/natives.json). None of the inspected FiveM drift scripts used them.

### Inferences
- GTA's grip model has a global "reduced grip" mode (a boolean + 0-3 level) that bypasses handling values; FiveM drift toggles rely on it rather than simulating slip. For a Roblox re-implementation, a "drift mode" is therefore best modelled as a multiplicative scale on the tyre friction curve (and the level 0-3 suggests discrete scale steps), not a separate physics model.
- Blumlaut's angle formula (heading vs planar velocity, ×0.5 scaling, 15° dead-zone, 30 km/h gate) is a ready-made slip-angle metric to replicate for parity testing between GTA and Roblox.
- Surface grip lives in data tables (materials / tyre-heat curves) that a server can re-stream, so per-surface friction multipliers are part of GTA's model and should exist in the Roblox port.

### Gaps
- Exact numerical effect of `SetVehicleReduceGrip` and of each `SetVehicleReduceGripLevel` level (0-3) on lateral/longitudinal grip is undocumented; no FiveM resource found that measured it.
- `SetVehicleReduceTraction` quoted in the Quags thread does not appear under that name in the inspected NativeDB query; could not confirm its hash/semantics.
- DriftV, RS TunerChip, jg-/paid drift systems: physics code not inspected (paid/escrowed or not read).

## Q2 — Which realism scripts exist (failure/damage, ESC/TC/ABS, limiters/cruise, manual transmissions, nitrous/turbo), and what do they reveal?

### Takeaway
Realism resources overwhelmingly work by (a) overriding handling fields per vehicle with `SetVehicleHandlingFloat` (+ `ModifyVehicleTopSpeed` to make drive-force/top-speed changes apply), (b) scaling engine output every frame with `SetVehicleCheatPowerIncrease` / `SetVehicleEngineTorqueMultiplier`, and (c) on newer builds, reading/writing per-wheel state (`GetVehicleWheelSpeed`, `SetVehicleWheelBrakePressure`). Manual gearboxes exploit `SetVehicleHighGear` to freeze GTA's automatic box, then emulate ratios by rescaling `fInitialDriveForce`/`fInitialDriveMaxFlatVel` — or, on recent builds, call the new `SetVehicleGearRatio`. RPM is normalised 0-1.

### Cited Findings

**ABS / TCS / ESP**
- **RAPTOR — Realistic Active Power Torque & Oversteer Regulation (author "Azure"/MadebyAzure, `TheStoicBear/RAPTOR`; free, public repo, no licence file; v3.0.1)** — [Cfx.re thread](https://forum.cfx.re/t/raptor-realistic-active-power-torque-oversteer-regulation/5324227), [README](https://github.com/TheStoicBear/RAPTOR/blob/main/README.md):

**Key native semantics these scripts rely on (docs)**
- `SET_VEHICLE_CHEAT_POWER_INCREASE` (alias `_SET_VEHICLE_ENGINE_TORQUE_MULTIPLIER`, 0xB59E4BD37AE292DB): "<1.0 decreased torque, =1.0 default, >1.0 increased torque. Negative values … go backwards… value is between 0.2 and 1.8 in the decompiled scripts. This needs to be called every frame to take effect." — [citizenfx/natives](https://github.com/citizenfx/natives/blob/master/VEHICLE/SetVehicleCheatPowerIncrease.md). Getter `GET_VEHICLE_CHEAT_POWER_INCREASE` is CFX-added — [native-decls](https://github.com/citizenfx/fivem/blob/master/ext/native-decls/GetVehicleCheatPowerIncrease.md).
- `MODIFY_VEHICLE_TOP_SPEED` (alias `_SET_VEHICLE_ENGINE_POWER_MULTIPLIER`, 0x93A3996368C94158): "the native you have to call when trying to apply handling changes related to fInitialDriveForce and fInitialDriveMaxFlatVel via SET_VEHICLE_HANDLING_FLOAT… will initiate transmission setup… it will also update the drag coefficient on the vehicle based on the percentage change"; `percentChange` 0-100, can exceed 100 — [citizenfx/natives](https://github.com/citizenfx/natives/blob/master/VEHICLE/ModifyVehicleTopSpeed.md). - `SET_VEHICLE_WHEELIE_STATE` / `GET_VEHICLE_WHEELIE_STATE` (CFX): states 1 = not wheeling, 65 = ready (burnouting), 129 = doing wheelie; example blocks wheelies for class 4 (muscle) — [SetVehicleWheelieState.md](https://github.com/citizenfx/fivem/blob/master/ext/native-decls/SetVehicleWheelieState.md).

### Inferences
- GTA's powertrain exposes two distinct runtime scalars: a per-frame torque scalar (`CheatPowerIncrease` = "EngineTorqueMultiplier") and a persistent top-speed/power modifier (`ModifyVehicleTopSpeed` = "EnginePowerMultiplier") that also changes drag — so in GTA top speed is reached when drive force equals drag, and raising "power" raises top speed by lowering drag. A Roblox port should model top speed as a drive-force/drag balance, with `fInitialDriveMaxFlatVel` setting the gear spacing, rather than a hard cap.
- Because manual gearboxes must emulate ratios by rescaling `fInitialDriveForce` (×ratio) and `fInitialDriveMaxFlatVel` (÷ratio), GTA's drivetrain is effectively "force = drive force × gear ratio, limited per gear by max flat velocity / ratio"; the RPM value is normalised (0-1) and derived from wheel speed vs gear band, not from an engine inertia model.
- Old ABS/TCS scripts compare averaged wheel speed with body speed; they demonstrate that GTA exposes enough per-wheel state to compute a longitudinal slip ratio per wheel, which is the exact quantity a Roblox tyre model needs to calibrate.
- RAPTOR multiplies `GetVehicleWheelSpeed` by 3.6 to compare with `GetEntitySpeed*3.6` — implying wheel speed is in m/s at the tyre surface (consistent with the "speed of a wheel at the tyre" doc). The original Muhaddil script does the same ×3.6.

### Gaps
- No FiveM resource was found that implements anti-rollover via physics forces (only rollover *detection*); no gravity/airtime script with inspected source beyond the AI-generated drift-system.
- Paid scripts (SHA4OW ABS/TCS, Quags Drift, Real Vehicle Transmission, kq_realoffroad) are escrowed; their algorithms are unknown.
- `GET_VEHICLE_CLUTCH`/`SET_VEHICLE_CLUTCH`: no documented range; Muhaddil sets 0.2 (failure simulation), but the semantic direction (0 = disengaged or engaged?) is not documented in native-decls.

## Q3 — Which FiveM resources expose or log per-wheel telemetry, or are handling editors with live readouts? (reusable as a frame-by-frame telemetry recorder)

### Takeaway
There is no single open FiveM "data logger" that already records every requested channel, but four open-source resources together cover them and are directly reusable: **jds-physicsEngine telemetry** (speed, gear, RPM, steering, throttle, brake, per-wheel suspension compression, g-forces), **NischGTM fivem-motion-telemetry** (pose/accelerations streamed over WebSocket to localhost — the best export pipeline), **1amZach handlingeditor** (MIT; live telemetry + exact handling.meta↔memory unit conversions), and **cortex-lib vehicleReplay** (robust per-wheel rotation-speed/compression capture). Per-wheel speed, power, brake pressure, traction vector, steering angle, clutch, turbo, etc. come from the CFX-added `GET_VEHICLE_WHEEL_*` family.

### Cited Findings

**Telemetry / recorder candidates (ranked by reuse value)**
1. **fivem-motion-telemetry ("nisch-telemetry", NischGTM; no licence file; ~200-line client)**: client-only, read-only; reads `GetEntityRotation(veh,2)` (pitch/roll/yaw), `GetEntityVelocity`, `GetEntityForwardVector`, `GetEntityCoords`, `GetEntitySpeed`, `GetVehicleCurrentRpm`, `GetVehicleCurrentGear`, `GetVehicleSteeringAngle`, `GetVehicleThrottleOffset` (clamped 0-1), brake `GetControlNormal(0,72)`; NUI page forwards data over WebSocket to a localhost motion-sim controller ("same NUI WebSocket pattern used by SaltyChat and TokoVOIP") — [README](https://github.com/NischGTM/fivem-motion-telemetry/blob/master/README.md), [client.lua](https://github.com/NischGTM/fivem-motion-telemetry/blob/master/client.lua). Best template for streaming frames off-box to a CSV/analysis tool.
2. **jds-physicsEngine — "Forza-Inspired Telemetry" (JustDevelopmentStudio; 7★; no licence)**: every 50 ms reads speed (`GetEntitySpeed*2.23694` mph), gear, RPM, `GetVehicleWheelSuspensionCompression(veh, 0..3)`, `GetVehicleSteeringAngle`, throttle/brake `GetControlNormal(0,71/72)`, simulated tyre temps/wear, and derives lateral/longitudinal g by differencing `GetEntityVelocity` over `GetGameTimer` dt and projecting on the right/forward vectors (÷9.81) — [client/telemetry.lua](https://github.com/JustDevelopmentStudio/jds-physicsEngine/blob/main/client/telemetry.lua).
3. **handlingeditor (IamZach / 1amZach; MIT; ox_lib)**: in-game editor of 42 CHandlingData fields with live telemetry (speed, RPM, gear, lateral & longitudinal g, top speed, automatic 0-100 km/h timer), state-bag sync with server-side clamping, export to `<Item type="CHandlingData">`. Crucially documents in-memory vs handling.meta units: "steering lock and the lateral traction curve are radians, top speed is divided by 3.6, the front bias fields are doubled, damping is divided by 10 and drag by 10,000"; `fDriveBiasFront` 1.0 in memory can mean pure FWD or 50/50 (editor checks which wheels are powered); "A few (gears, some suspension values) only fully settle after the car moves a bit or is respawned"; only CHandlingData (no flags/sub-handling) — [README](https://github.com/1amZach/handlingeditor/blob/main/README.md).
4. **cortex-lib `imports/vehicleReplay` (IEver3st; licence "other")**: shared wheel telemetry capture for "Director and Rewind": per wheel (up to 10) stores `GetVehicleWheelRotationSpeed` ("angular velocity, not Xrot/YRotation") and `GetVehicleWheelSuspensionCompression` ("Compression is read-only: Cfx has no corresponding per-wheel setter"), with NaN/inf guards and feature-detection of natives by name for older game builds; replays with `SetVehicleWheelRotationSpeed` — [client.lua](https://github.com/IEver3st/cortex-lib/blob/main/imports/vehicleReplay/client.lua).
5. **fivem-handling-editor (carmineos; MIT; 53★, the reference FiveM handling editor, C#/MenuAPI)**: per-vehicle edits synced via decorators; limitations noted: "Some fields don't seem to have any effect after being edited", "Some fields require the car to move a bit or to be damaged to update", "Some Int fields have a wrong type in the ExtraNative, so I disabled them (nInitialDriveGears)", flags unsupported, some fields only work when edited globally — [README](https://github.com/carmineos/fivem-handling-editor/blob/master/README.md).
- Others: `FRANkiller13/FiveM-Handling-Editor` (GPL-3.0, ESX), `Dking07/fivem-handling-editor` (GPL-3.0), `EnderDevelopment/fivem-handling-editor`, `PrestigeRoleplay/fivem-handling-presets` (MIT, "10 ready-to-use FiveM handling presets — Street, Drift, Racing, Off-Road, Muscle"), `DefiledSpec/fivem-handling-meta` ("GTAV vehicle handling files extracted from the base game") — [GitHub search "fivem handling"](https://github.com/search?q=fivem+handling&type=repositories). A debug/admin "koil-debug" and NoPixel-style admin menus calling `GetVehicleWheelSuspensionCompression` circulate in leaked server dumps (not recommended to reuse; licence/provenance problems) — [GitHub code search](https://github.com/search?q=GetVehicleWheelSuspensionCompression&type=code).
- "Double-clutch" scripts in several RP frameworks (e.g. `mercy-misc/client/cl_doubleclutch.lua`, `qb-vehicles/cl_doubleClutch.lua`) read `GetVehicleWheelSuspensionCompression` — [GitHub code search](https://github.com/search?q=GetVehicleWheelSuspensionCompression&type=code) (purpose not verified).

**Server-side handling packs**

### Inferences
- A complete GTA recorder can be built in ~150 lines by merging nisch-telemetry's WebSocket export with jds/cortex's per-wheel loops and adding the missing channels from the table (wheel speed, rotation speed, power, brake pressure, traction vector length, per-wheel steering angle, surface material, clutch, turbo, handbrake). It should run in a `Wait(0)` thread (per-frame) and timestamp with `GetGameTimer()`/`GetFrameTime()`; the inspected tools sample at 50 ms, which is too coarse for tyre transients.
- Comparing `GET_VEHICLE_WHEEL_SPEED` (tyre surface speed) with `GET_VEHICLE_WHEEL_ROTATION_SPEED` (angular velocity) frame-by-frame directly yields each wheel's effective rolling radius, and comparing wheel speed with body velocity projected on each wheel yields the longitudinal slip ratio — the two quantities most needed to fit a Roblox tyre curve.
- Handling values read with `GetVehicleHandlingFloat` are in memory units (radians, m/s, ×2 bias, ÷10 damping, ÷10,000 drag per 1amZach); a Roblox port that imports handling.meta must apply the same conversions or it will be off by those factors.
- Because some handling fields "only settle after the car moves or is respawned" and `ModifyVehicleTopSpeed` is needed to re-run transmission setup, any calibration run that changes handling must respawn or re-initialise the vehicle before logging.

### Gaps
- No open FiveM resource was found that logs **all** channels to file per frame (no "MoTeC-style" data logger); the closest are the four above.
- Units/ranges for `GET_VEHICLE_WHEEL_TRACTION_VECTOR_LENGTH`, `GET_VEHICLE_WHEEL_POWER`, `GET_VEHICLE_CLUTCH`, `GET_VEHICLE_TURBO_PRESSURE`, `GET_VEHICLE_GRAVITY_AMOUNT` and `GET_VEHICLE_WHEEL_SUSPENSION_COMPRESSION` (metres vs normalised) are not documented in native-decls; must be determined empirically.
- No FiveM port of Real-Time Handling Editor-style live graphs (e.g. traction curves plotted against measured slip) was found.

## Q4 — What do the Cfx.re native docs / NativeDB say precisely about the vehicle-physics natives (units, ranges, side effects), especially FiveM's extra natives?

### Takeaway
The CFX-added natives (`GET_VEHICLE_WHEEL_*`, `GET/SET_VEHICLE_HANDLING_*`, clutch/RPM/gear/turbo/gravity getters-setters) are thin memory accessors whose docs mostly give signatures only — ranges and units are largely undocumented. ### Inferences
- GTA's default gravity is 9.8 m/s² (`SET_GRAVITY_LEVEL` 0), and the per-vehicle `SET_VEHICLE_GRAVITY_AMOUNT` presumably uses the same m/s² scale (unconfirmed); Roblox's default `workspace.Gravity` is in studs/s², so unit conversion is needed.
- The existence of separate "rotation speed" (rad/s) and "wheel speed" (m/s at tyre) getters, a per-wheel traction-vector length, per-wheel powered flag and per-wheel brake pressure confirms GTA's model is a per-wheel ray/collider tyre model (with tyre and rim colliders) with brake-pressure and drive-power distribution per wheel — a structure a Roblox raycast-wheel controller can mirror one-to-one.

### Gaps
- No official ranges/units for clutch, RPM (only community statement 0-1), turbo pressure, gravity amount, traction vector length, wheel power, or suspension compression; docs.fivem.net pages render from the same native-decls sources and add nothing further (the docs.fivem.net HTML itself was not separately fetched).
- `SET_VEHICLE_TRACTION_CONTROL`-style native: none found in NativeDB under that name; GTA's TCS-like behaviour (if any) is not exposed as a toggle.
