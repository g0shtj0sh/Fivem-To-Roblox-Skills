## Q1. What each parameter controls, units, typical ranges (parameter reference)

### Takeaway
Most `handling.meta` values are not SI quantities but *multipliers on accelerations expressed in g* (drive force, brake force, traction), and the game converts several of them at load time (drag ÷10000, max flat vel ÷3.6 and ×1.2, steering/slip angles deg→rad, all `*BiasFront` → two per-axle multipliers `2·b` and `2·(1−b)`, damping ÷10). `fMass` only matters for collisions/impulses because forces are scaled by mass internally; a Roblox port should therefore treat drive/brake/grip numbers as accelerations (g) and multiply by mass to obtain forces.

### Cited Findings

#### A. Load-time conversions (file value → in-memory CHandlingData) — VERIFIED via ikt's editor code (it writes these exact transforms into live game memory, mirroring what the game's loader produces)
- `fInitialDragCoeff(mem) = file / 10000` — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp); same "divided by 10000 internally" claim at [xgamingserver tool](https://xgamingserver.com/tools/fivem/handling-meta) and EDDLM uses `fInitialDragCoeff * 0.0001` — [EDDLM](https://eddlm.github.io/Handling-Tools/handling)
- `fPercentSubmerged` kept; extra field `fSubmergedRatio = 100 / fPercentSubmerged` (so the file value is a percentage, e.g. 85.0) — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- `fDriveBiasFront`: if file==1.0 → front=1.0, rear=0.0; if file==0.0 → front=0.0, rear=1.0; otherwise front = `2·b`, rear = `2·(1−b)` — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- `fInitialDriveMaxFlatVel(mem) = file / 3.6` (km/h → m/s) and a derived `fDriveMaxFlatVel(mem) = file / 3.0` (= file/3.6 × 1.2) — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- `fBrakeBiasFront` → front `2·b`, rear `2·(1−b)` — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- `fSteeringLock(mem) = deg2rad(file)`, plus `fSteeringLockRatio = 1/deg2rad(file)`; ikt: "Steering lock appears to be in radians for the inner wheel, while handling.meta uses degrees" — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp); [ikt GTAForums](https://gtaforums.com/topic/869574-chandlingdata-in-memory/)
- `fTractionCurveMaxRatio = 1/fTractionCurveMax`; `fTractionCurveRatio = 1/(fTractionCurveMax − fTractionCurveMin)` — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- `fTractionCurveLateral(mem) = deg2rad(file)`, `fTractionCurveLateralRatio = 1/deg2rad(file)` — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- `fTractionSpringDeltaMaxRatio = 1/fTractionSpringDeltaMax` — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- `fTractionBiasFront` → front `2·b`, rear `2·(1−b)` — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- `fSuspensionCompDamp(mem) = file/10`, `fSuspensionReboundDamp(mem) = file/10`; `fSuspensionForce`, limits, raise copied as-is — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- `fSuspensionBiasFront` and `fAntiRollBarBiasFront` → front `2·b`, rear `2·(1−b)` — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- All other CHandlingData fields (mass, COM, inertia, drive force, drive inertia, clutch rates, brake force, handbrake, low-speed loss, camber stiffness, traction loss mult, anti-roll force, roll centres, damage mults, petrol/oil, seat offset, monetary value, flags) are copied unchanged; CCarHandlingData fields (toe, camber, castor, engine resistance, max drive bias transfer, jump force scale, back-end pop-up) are copied unchanged — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- Memory layout (b791–b1604 era): handlingName hash 0x08, fMass 0x0C, fInitialDragCoeff 0x10, fDownforceModifier 0x14, fPopUpLightRotation 0x18, COM 0x20, inertia 0x30, fPercentSubmerged 0x40, fSubmergedRatio 0x44, fDriveBiasFront 0x48, fDriveBiasRear 0x4C, nInitialDriveGears 0x50 (uint8), fDriveInertia 0x54, clutch up/down 0x58/0x5C, fInitialDriveForce 0x60, fDriveMaxFlatVel 0x64, fInitialDriveMaxFlatVel 0x68, fBrakeForce 0x6C … fRollCentreHeightRear 0xEC, damage mults 0xF0–0xFC, petrol 0x100, oil 0x104, seat offsets 0x10C–0x114, nMonetaryValue 0x118, model/handling/damage flags 0x11C/0x120/0x124, AIHandling hash 0x134 — [ikt GTAForums](https://gtaforums.com/topic/869574-chandlingdata-in-memory/); [IKT struct](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/Memory/HandlingInfo.h). Note: a 2025/26 FiveM issue calls offset 0x4C "m_acceleration" and says cheats modify it — [citizenfx/fivem#3889](https://github.com/citizenfx/fivem/issues/3889) — whereas ikt's layout has 0x4C = fDriveBiasRear (layout may differ by build or the issue mislabels it; unresolved).
- FiveM `GET_VEHICLE_HANDLING_FLOAT` "Returns the effective handling data of a vehicle"; field names "match the keys in handling.meta"; only "CHandlingData" class supported by the float getter — [cfxnatives](https://cfxnatives.dev/natives/GET_VEHICLE_HANDLING_FLOAT)

#### B. Physical attributes
- **handlingName** — key used by vehicles.meta; ≤16 chars per GTAMODS — [GTAMODS](https://gtamods.com/wiki/Handling.meta); DWNSTR says max 14 chars — [DWNSTR](https://docs.dwnstr.com/data-files/handling); stored in memory as a hash at 0x08 — [IKT struct](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/Memory/HandlingInfo.h)
- **fMass** (kg) — "Only used when the vehicle collides with another vehicle or non-static object" — [GTAMODS](https://gtamods.com/wiki/Handling.meta); "does not impact performance or handling behaviour in any way" — [GTACARS](https://gtacars.net/gta5/glossary); "Does not affect handling" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); "Mass is not at all related to physical agility" — [EDDLM](https://eddlm.github.io/Handling-Tools/handling). Typical 1000–2500 for cars (e.g. 1745 in ikt's sample, 2000 in DWNSTR sample) — [IKT sample](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingItem.h); [DWNSTR](https://docs.dwnstr.com/data-files/handling)
- **fInitialDragCoeff** — "drag coefficient on the rage physics archetype of the vehicle (proportional to velocity squared)… Greater value will lower the maximum speed", value 10–120 — [GTAMODS](https://gtamods.com/wiki/Handling.meta); EDDLM gives air resistance in g as `(Speed_mps · fInitialDragCoeff·0.0001)^2` and says drag and torque "are measured in G-Forces, the speed at which they even out is the vehicle's top speed"; "drag is omnidirectional" — [EDDLM](https://eddlm.github.io/Handling-Tools/handling); ikt: "Formula: DragCoefficientCd/10 … Formula uncertain, but seems to yield realistic results" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json)
- **fDownforceModifier** — grip-at-speed; GTAMODS value "TBD" — [GTAMODS](https://gtamods.com/wiki/Handling.meta). Disassembly-derived rules ("wheel downforce value", WDV, per wheel; regular cars): no fDownforceModifier → flat WDV 0.035 (0.07 with custom spoiler); "old-style" (modifier ≤100): WDV 0 at standstill rising "exponentially" to cap `fDownforceModifier × 0.035` at >90% of fInitialDriveMaxFlatVel, ×1.25 with spoiler, and modifier ≤1.0 disables the dynamic calc; "new-style" (>100): flat `(mod/100)·0.035·0.3` up to 40% top speed, rising to cap `(mod/100)·0.035·0.86` at >90%, ×1.25 with spoiler, and is deliberately skipped in Single Player; open-wheel (strAdvancedFlags 0x8000000): `(mod·0.07·0.3)+0.035` at rest → cap `(mod·0.07)+0.035` at >95% top speed; wing broken → modifier ÷5 for that axle — [GTACARS-DF](https://gtacars.net/gta5/downforce) (exact Desmos formulas linked there). Also: "there's a natural downforce in the game that affects all cars… cars are visibly pushed down at higher speeds" — [GTACARS-DF](https://gtacars.net/gta5/downforce). EDDLM: the result "is added to the wheel grip", ×number of wheels; downforce is "two behaviors - an actual down force pressing the car down, and a separate grip gain" — [EDDLM](https://eddlm.github.io/Handling-Tools/handling). ikt: "Usable range in SP: 1.0 to 100.0", "Downforce tops out at 90% of fInitialDriveMaxFlatVel" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json)
- **fPopUpLightRotation** — overrides `light_cover` bone rotation angle — [GTAMODS](https://gtamods.com/wiki/Handling.meta)
- **fPercentSubmerged** — % of vehicle height in water before it floats/sinks; road vehicles default 85 — [GTAMODS](https://gtamods.com/wiki/Handling.meta); "How deep the vehicle can be submerged in water before drowning, as a percent of the model's height" — [GTACARS](https://gtacars.net/gta5/glossary). File value is percent (85.0), as shown by `fSubmergedRatio = 100/value` — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp) and vanilla sample `85.000000` — [DWNSTR](https://docs.dwnstr.com/data-files/handling)
- **vecCentreOfMassOffset** (m, model space; +x right, +y forward, +z up) — default COM is model origin (0,0,0); range ~±5 (GTAMODS) / ±10 (DWNSTR); large negative z (≈−10) gives erratic behaviour — [GTAMODS](https://gtamods.com/wiki/Handling.meta); [DWNSTR](https://docs.dwnstr.com/data-files/handling). ikt's editor applies it at runtime with `PHYSICS::SET_CGOFFSET` — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- **vecInertiaMultiplier** (unitless multiplier on rotational inertia per axis; x = pitch, y = roll, z = yaw) — "Recommend keeping the z value above 2.0 unless you want arcade style immediate reaction to steering inputs"; range 0–4; "Motorcycles do not use this attribute at all"; police3, Gang Burrito, 190Z, Zion Classic "do not respond typically" — [GTAMODS](https://gtamods.com/wiki/Handling.meta); higher = "takes more time to rotate or stop rotating" — [GTACARS](https://gtacars.net/gta5/glossary)

#### C. Transmission / engine
- **fDriveBiasFront** — 0 = RWD, 1 = FWD, 0.5 = equal — [GTAMODS](https://gtamods.com/wiki/Handling.meta); "Values greater than 0.9 snap to 1, and values less than 0.1 snap to 0" — [GTACARS](https://gtacars.net/gta5/glossary) and [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json). In memory, split into per-axle multipliers `2b` / `2(1−b)` (see §A).
- **nInitialDriveGears** — forward gears; 1–8 before b1604, 1–10 from b1604; "Higher values … overwrite other data"; >8 can cause downshift problems — [GTAMODS](https://gtamods.com/wiki/Handling.meta); ikt: "b1493 and older: top gear is 7… b1604 and newer, top gear is 10… Vehicles have shorter gears for gears 7 and up… can't properly downshift from 8th gear and up" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); "All transmission upgrades increase this value by 1" — [GTACARS](https://gtacars.net/gta5/glossary). Gear ratios are stored per vehicle in memory (an array indexed by gear) and the max speed of a gear is `fDriveMaxFlatVel / ratio[gear]` (ikt uses this everywhere, e.g. `maxSpeed = DriveMaxFlatVel / ratios[gearCurr]`) — [IKT-MT script.cpp](https://github.com/ikt32/GTAVManualTransmission/blob/master/Gears/script.cpp)
- **fInitialDriveForce** — "drive force of the car, at the wheels", `= TorqueWheelsNm/WeightKg`, most cars 0.10–0.40 — [GTAMODS](https://gtamods.com/wiki/Handling.meta); "baseline acceleration of approximately `10 * InitialDriveForce` m/s²", `baseTorqueNm = fInitialDriveForce * fMass`, "torque curve being flat until 80% RPM (then dropping to 60% torque)" — [GTACARS](https://gtacars.net/gta5/glossary); "TorqueNm/CurbWeightKg… flat-ish torque curve, reducing torque after 80% RPM to 60% torque" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); "dictates the target acceleration… measured in G-Forces… Gearing modulates this value in ratios"; in-game metric = `fInitialDriveForce × ratio of current gear` (g); "Electric vehicles bypass this entirely, starting with x5 torque which drains to x1 at the top speed" — [EDDLM](https://eddlm.github.io/Handling-Tools/handling)
- **fDriveInertia** — engine rev rate; 1.0 = default; "Bigger value = quicker redline"; "a max change rate cap for the rpm… will not increase your rate of forward acceleration under normal circumstances. values below 0.5 may slow down cars with high acceleration"; formula "TBD" — [GTAMODS](https://gtamods.com/wiki/Handling.meta); EDDLM: idle→redline time ≈ `1 / fDriveInertia` s at full throttle — [EDDLM](https://eddlm.github.io/Handling-Tools/handling); ikt: applies "while drive is not engaged (handbrake, or clutch/neutral)" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json). ikt's own fake-rev emulation (not game code) uses `ΔRPMnorm = throttle · 2·fDriveInertia·dt` on RPM normalized 0–1, with comment "For some reason, first gear revs slower" — [IKT-MT script.cpp](https://github.com/ikt32/GTAVManualTransmission/blob/master/Gears/script.cpp)
- **fClutchChangeRateScaleUpShift / DownShift** — "A value of 1 = 0.9 seconds to shift gears", bigger = faster, "Recommended to not go over 13" — [GTAMODS](https://gtamods.com/wiki/Handling.meta); `ShiftTime = 0.9 / value` (0.5→1.8 s, 2→0.45 s) — [GTACARS](https://gtacars.net/gta5/glossary); [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); EDDLM instead uses `1 / value` seconds — [EDDLM](https://eddlm.github.io/Handling-Tools/handling)
- **fInitialDriveMaxFlatVel** (file unit ≈ km/h-like) — "speed at redline in top gear… does not guarantee the vehicle will reach this speed. ×0.82 → mph, ×1.32 → km/h; km/h×0.75 → value; mph×1.22 → value", `TopSpeedKph = (fInitialDriveMaxFlatVel*1.2)/0.9`, "GTA V uses a ratio of 0.9 for the top gear by default", other gears: replace 0.9 by that gear's ratio — [GTAMODS](https://gtamods.com/wiki/Handling.meta); "Formula: TopGearMaxSpeedKph*0.75… Top gear might not be the longest gear… fInitialDriveForce and fInitialDragCoeff impact actual top speed" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); EDDLM: km/h = value/0.75; "Over this speed, the engine power will degrade greatly" — [EDDLM](https://eddlm.github.io/Handling-Tools/handling); "Essentially specifies the final drive ratio" — [GTACARS](https://gtacars.net/gta5/glossary). In memory: `value/3.6` m/s and `fDriveMaxFlatVel = value/3.0` m/s (§A).
- **fBrakeForce** — multiplier on deceleration, 1.0 unmodified; "To use all of a vehicles traction for braking fBrakeForce must be higher than fTractionCurveMax / 4 (only tested with cars)" — [GTAMODS](https://gtamods.com/wiki/Handling.meta); EDDLM: "How many Gs of deceleration are applied to each wheel… Assuming perfect balance, a fourth of brake is enough to make each wheel lockup"; at 1.0 "60-0 mph in ~1.71s" — [EDDLM](https://eddlm.github.io/Handling-Tools/handling); ikt: set "just high enough that wheels lock up or ABS kicks in" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json)
- **fBrakeBiasFront** — 0 rear only, 1 front only, 0.5 even; >0.5 does not guarantee fronts lock first — [GTAMODS](https://gtamods.com/wiki/Handling.meta); best ~0.55–0.7 — [EDDLM](https://eddlm.github.io/Handling-Tools/handling); in memory front `2b`, rear `2(1−b)` (§A)
- **fHandBrakeForce** — handbrake braking power; on/off (not analog); only rear wheels — [GTAMODS](https://gtamods.com/wiki/Handling.meta); [GTACARS](https://gtacars.net/gta5/glossary); [EDDLM](https://eddlm.github.io/Handling-Tools/handling)
- **fSteeringLock** (degrees; ~40 typical, 1–90) — max steered-wheel angle; game's speed-dependent steering assist "simply uses a percentage of the original steering lock"; rule of thumb `fSteeringLock ≈ fTractionCurveLateral·1.25 + 10` (22.5 → ~38) — [GTAMODS](https://gtamods.com/wiki/Handling.meta); "How much the vehicle's inner wheel will turn when stopped… At higher speeds, steering angle is reduced from this maximum" — [GTACARS](https://gtacars.net/gta5/glossary)

#### D. Wheel traction
- **fTractionCurveMax** (formerly fTractionMult) — peak grip coefficient — [GTAMODS](https://gtamods.com/wiki/Handling.meta); "values roughly equate to g's of grip (such that a value of 1 means cornering at 1g)" — [GTACARS](https://gtacars.net/gta5/glossary); "1.0 allows for about 1g of cornering grip"; realistic ballparks 90's tyres 1.15, eco 1.22, street 1.28, semi-slick 1.37, slicks 1.55–1.60 — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); EDDLM: grip = "how much the vehicle's tires are able to accelerate or decelerate the car's body", "constantly changed around by context, like suspension pressure, surface" — [EDDLM](https://eddlm.github.io/Handling-Tools/handling). Vanilla sports cars use ~2.4–2.6 (e.g. 2.62/2.38 in ikt sample) — [IKT sample](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingItem.h)
- **fTractionCurveMin** (formerly fTractionLoss) — sliding grip (post-peak, wheelspin, lock-up) in ≈g — [GTAMODS](https://gtamods.com/wiki/Handling.meta); [GTACARS](https://gtacars.net/gta5/glossary); advice ~10% below Max — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json)
- **fTractionCurveLateral** (degrees; vanilla default 22.5) — "Shape of lateral traction curve (peak traction position in degrees sideways = fTractionCurveLateral / 2)" — [GTAMODS](https://gtamods.com/wiki/Handling.meta); "The vehicle will tend to stay below half of this value… keep it at default 22.5… Sports and Supercars… as low as 18º… Over 24º is not recommended save for the slidiest cars" — [EDDLM](https://eddlm.github.io/Handling-Tools/handling); "The full angular range… maximum angle the vehicle's tyre can handle… before the wheels start to slide and revert from fTractionCurveMax to fTractionCurveMin" — [GTACARS](https://gtacars.net/gta5/glossary); "Optimal slip angle before grip decreases. In degrees… street tires: 9.3-8.5, semi-slicks 7.5, slicks 6.0" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json). Stored in radians + reciprocal (§A).
- **fTractionSpringDeltaMax** (m) — "Max distance of the lateral sidewall travel"; produces a force pulling the car back, "most noticeable when stopping after a slide" — [GTAMODS](https://gtamods.com/wiki/Handling.meta); [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); "A value of 0 equates to a completely hard stop" — [GTACARS](https://gtacars.net/gta5/glossary)
- **fLowSpeedTractionLossMult** — "How much traction is reduced at low speed, 0.0 means normal traction… mainly car burnout… Default is 1.0. A completely artificial force" — [GTAMODS](https://gtamods.com/wiki/Handling.meta); approx low-speed traction `1 / (1 + fLowSpeedTractionLossMult)` (1.0 → about half grip) — [GTACARS](https://gtacars.net/gta5/glossary); "Turn this off (0.0) or set it very low for realistic behavior" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json)
- **fCamberStiffnesss** (triple "s" is the real tag) — "How much the vehicle is pushed towards its roll direction… Values smaller than 0.0 or greater than 1.0 create unrealistic forces" — [GTAMODS](https://gtamods.com/wiki/Handling.meta); "Negative: Uphill force; 0.0: none; Positive: Downhill force" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); "lateral force pushing the vehicle towards its roll direction (chassis roll relative to the world), when tires are on the ground" — [GTACARS](https://gtacars.net/gta5/glossary)
- **fTractionBiasFront** — 0.01–0.99; 0.0 or 1.0 → "the tires actually fail to spawn"/no traction — [GTAMODS](https://gtamods.com/wiki/Handling.meta); ~0.48 balanced — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); in memory front `2b`, rear `2(1−b)` (§A) — so b=0.5 gives ×1.0 per axle.
- **fTractionLossMult** — scales grip change from surface materials (materials.dat); "1.0: Base grip loss as defined in materials.dat" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); also loses "top speed" on low-grip surfaces — [GTACARS](https://gtacars.net/gta5/glossary); "High end cars can have up to 1.5 or so before… negative grip" — [EDDLM](https://eddlm.github.io/Handling-Tools/handling)

#### E. Suspension
- **fSuspensionForce** — Rockstar-style comment: "1 / (Force * NumWheels) = Lower limit for zero force at full extension" — [GTAMODS](https://gtamods.com/wiki/Handling.meta); ikt flags this as "Rockstar Games documentation, unclear what it means… More research for formula and units required" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); higher = stiffer — [GTACARS](https://gtacars.net/gta5/glossary). Typical 1.6–2.5 — [DWNSTR](https://docs.dwnstr.com/data-files/handling); [IKT sample](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingItem.h)
- **fSuspensionCompDamp / fSuspensionReboundDamp** — compression/rebound damping, bigger = stiffer — [GTAMODS](https://gtamods.com/wiki/Handling.meta); "If this value is set to fSuspensionForce/2 it perfectly cancels the compression [rebound] in 1 bounce" — [GTACARS](https://gtacars.net/gta5/glossary); "CompDamp over half fSuspensionForce can reduce grip on compression… Comp + Rebound = fSuspensionForce gives a stable ride" — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); stored ÷10 (§A)
- **fSuspensionUpperLimit / fSuspensionLowerLimit** (m, relative to rest; Upper = compression travel e.g. 0.09–0.10, Lower = extension e.g. −0.10/−0.14) — [GTACARS](https://gtacars.net/gta5/glossary); [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); [DWNSTR sample](https://docs.dwnstr.com/data-files/handling)

- **fAntiRollBarForce** — "spring constant that is transmitted to the opposite wheel when under compression… Larger Numbers = less body roll" — [GTAMODS](https://gtamods.com/wiki/Handling.meta); formula undocumented — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json)

### Inferences
- Because the game stores `1/(Max−Min)` and `1/LateralRad`, the lateral grip curve is very likely a piecewise function of normalized slip `s = slipAngle / fTractionCurveLateral(rad)` that rises to `fTractionCurveMax` and then falls linearly toward `fTractionCurveMin` (the reciprocal fields are the typical precomputed divisors of such a lerp). The exact piecewise shape (where the peak sits: at `s=0.5` per GTAMODS/EDDLM or `s=1` per GTACARS/ikt) is not documented from disassembly in the sources found.
- `*BiasFront → (2b, 2(1−b))` means each axle's share is a multiplier around 1.0 that keeps the sum = 2 (for a 2-axle car). For a Roblox port: per-wheel value = base × axleMult, then for traction/drive divide over wheels on that axle.
- Since drive, brake and grip are all expressed in g-like units and fMass "does not affect handling", the engine probably computes forces as `value × mass × g` (or impulses scaled by mass). Re-implementation: `F_drive_total ≈ fInitialDriveForce · gearRatio · torqueCurve(rpm) · mass · 9.8` distributed by drive-bias multipliers; `a_drag(g) ≈ (v · Cd·1e-4)^2`-type term (EDDLM's empirical formula) — treat drag formula as approximate.
- Top speed in top gear at redline (m/s) = `fInitialDriveMaxFlatVel/3.0 / 0.9`; in km/h = `fInitialDriveMaxFlatVel × 1.333`; per gear `v_max(g) = fDriveMaxFlatVel / ratio[g]`. Actual top speed is lower when drag ≥ drive accel before redline, and torque falls to 60% above 80% RPM.

### Gaps
- No disassembly-backed source found for: the exact traction-curve function, the exact `fSuspensionForce` spring law (units), anti-roll bar formula, `fDriveInertia` RPM integration law inside the game, `fLowSpeedTractionLossMult` exact speed window (GTACARS gives only an approximation), `fCamberStiffnesss` force law, `fTractionSpringDeltaMax` spring constant.
- The stock gear-ratio table per `nInitialDriveGears` (other than top gear = 0.9 and CVT 5.0→0.9) was not found in a citable source; ikt's Manual Transmission reads them from memory at runtime rather than documenting them — [IKT-MT](https://github.com/ikt32/GTAVManualTransmission/blob/master/Gears/script.cpp).
- `fEngineResistance`, `fBackEndPopUpBuildingImpulseMult`, `fIncreasedRammingForceScale`, `nMonetaryValue`: no observed/documented effect.
- I did not find any source distinguishing GTA V Legacy vs Enhanced handling semantics; all sources predate or ignore Enhanced.
- Vespura's handling docs URL (docs.vespura.com/gtav/handling/) returned 404; not used.

## Q2. Known / reverse-engineered formulas

### Takeaway
The best-established formulas are: max-flat-vel conversions (÷3.6, ×1.2, top-gear ratio 0.9 ⇒ km/h ≈ value×1.333), shift time `0.9/clutchScale` s, drive torque `fInitialDriveForce × mass` (flat to 80% RPM then 60%), low-speed grip `≈1/(1+mult)`, downforce WDV formulas (from disassembly), and bias splitting `2b / 2(1−b)`; drag, brakes and traction-curve shape remain empirical.

### Cited Findings
- `fDriveMaxFlatVel_mps = fInitialDriveMaxFlatVel / 3.0` and `fInitialDriveMaxFlatVel_mps = value / 3.6` — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- Per-gear redline speed `= DriveMaxFlatVel / gearRatio[gear]` (ikt's HUD/shift logic, reading game memory) — [IKT-MT ScriptHUD.cpp](https://github.com/ikt32/GTAVManualTransmission/blob/master/Gears/ScriptHUD.cpp); [IKT-MT script.cpp](https://github.com/ikt32/GTAVManualTransmission/blob/master/Gears/script.cpp)
- `TopSpeedKph = (fInitialDriveMaxFlatVel * 1.2) / 0.9`; top gear ratio 0.9 by default; convert: ×1.32 km/h, ×0.82 mph, kph×0.75, mph×1.22 — [GTAMODS](https://gtamods.com/wiki/Handling.meta); `TopGearMaxSpeedKph*0.75` — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); `value / 0.75` km/h — [EDDLM](https://eddlm.github.io/Handling-Tools/handling)
- Gear count semantics: top gear is not necessarily the longest; gears ≥7 shorter (ikt) vs "6th and 7th gear ratios are taller than the final gear ratio… (Based on old testing. Might only apply to older versions)" (GTAMODS) — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); [GTAMODS](https://gtamods.com/wiki/Handling.meta)
- CVT flag: ratio 5.0 at standstill → 0.9 at 90% of fInitialDriveMaxFlatVel — [GTACARS](https://gtacars.net/gta5/glossary); electric: torque ×5 draining to ×1 at top speed — [EDDLM](https://eddlm.github.io/Handling-Tools/handling)
- Drive: accel ≈ `10·fInitialDriveForce` m/s² baseline; `Torque_Nm = fInitialDriveForce·fMass`; torque flat to 80% RPM then down to 60% — [GTACARS](https://gtacars.net/gta5/glossary); [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); accel(g) = `fInitialDriveForce × currentGearRatio` — [EDDLM](https://eddlm.github.io/Handling-Tools/handling)
- Drive inertia: idle→redline ≈ `1/fDriveInertia` s — [EDDLM](https://eddlm.github.io/Handling-Tools/handling)
- Shift time: `0.9 / fClutchChangeRateScale*` s — [GTACARS](https://gtacars.net/gta5/glossary); [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json); [GTAMODS](https://gtamods.com/wiki/Handling.meta)
- Drag: `a_air(g) = (v_mps · fInitialDragCoeff · 0.0001)^2` — [EDDLM](https://eddlm.github.io/Handling-Tools/handling) (as printed; dimensionally odd, likely an empirical fit)
- Brakes: fBrakeForce = g of deceleration per wheel; lock-up threshold `fBrakeForce > fTractionCurveMax/4` — [EDDLM](https://eddlm.github.io/Handling-Tools/handling); [GTAMODS](https://gtamods.com/wiki/Handling.meta)
- Low-speed traction: `grip_lowspeed ≈ 1/(1+fLowSpeedTractionLossMult)` — [GTACARS](https://gtacars.net/gta5/glossary)
- Steering setup: `fSteeringLock ≈ 1.25·fTractionCurveLateral + 10` (estimate) — [GTAMODS](https://gtamods.com/wiki/Handling.meta)
- Damping: `Comp = Force/2` (or `Rebound = Force/2`) cancels oscillation in one bounce; `Comp + Rebound = Force` stable — [GTACARS](https://gtacars.net/gta5/glossary); [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json)
- Downforce WDV formulas (regular/old/new/open-wheel/active spoilers), with Desmos calculators reproducing disassembled code — [GTACARS-DF](https://gtacars.net/gta5/downforce); EDDLM summary: dynamic ruleset gains 0→`0.035·fDownforceModifier` at 90% top speed; static high (≤1.0) flat 0.035 (0.07 with spoiler); static low (≥100) flat 0.0105 (0.01313 with spoiler) — [EDDLM](https://eddlm.github.io/Handling-Tools/handling) (EDDLM's ≥100 numbers differ from GTACARS-DF's "new-style" formula; GTACARS-DF says that type is skipped in SP and falls back to a flat value, which may explain EDDLM's SP measurement)
- Toe = deg/45, camber ≈ deg/22.5, castor 0.01 = 1° — [GTAMODS](https://gtamods.com/wiki/Handling.meta)
- Gravity multipliers from offroad flags: ×1.1 (10.78 m/s²), ×1.2 (11.76 m/s²) — [GTACARS](https://gtacars.net/gta5/glossary); [GTAMODS](https://gtamods.com/wiki/Handling.meta)

### Inferences
- The "×1.2 / ÷3.6" pair: ÷3.6 is a plain km/h→m/s conversion; ×1.2 makes `fDriveMaxFlatVel` the speed at which the *engine* reaches max RPM with ratio 1.0; with top-gear ratio 0.9 the redline speed is `value·1.2/0.9 = 1.333·value` km/h. "Real" top speed is whichever is lower: that redline speed, or the speed where `driveAccel(v)` (with the 60% torque fall-off above 80% RPM) equals drag accel.
- Eddlm's in-tool example ("fInitialDriveMaxFlatVel 200 → last gear will top at 115.99 mph") does not match `200·1.333 km/h = 166 mph`; it likely includes other factors (or a different gear) — treat as unexplained.
- Eddlm's "60-0 mph in ~1.71 s" for fBrakeForce 1.0 implies ≈15.7 m/s² (≈1.6 g) total, which conflicts with a naive "1 g per wheel × 4 wheels"; brake accel is presumably capped by traction (fTractionCurveMax) — consistent with the `/4` lock-up rule.

### Gaps
- No source gives the in-game formula for how traction (fTractionCurveMax) is scaled by suspension load ("suspension pressure" is mentioned only qualitatively by EDDLM).
- No source documents ABS slip targets for MF_ABS_* beyond "minimal slip" vs "some slip".

## Q3. Disputed claims / myths vs verified

### Takeaway
Verified (memory/disassembly): load-time unit conversions, bias splitting, flat-vel ×1.2 relation, downforce rules, offroad gravity. Disputed: traction-curve peak position, anti-roll-bar bias direction, drive-bias snapping, clutch time constant, fPercentSubmerged units, CLOSE_RATIO_GEARBOX scope, ASSIST_TRACTION_CONTROL effect, and several old-tutorial descriptions (DWNSTR) that are wrong for GTA V.

### Cited Findings
- **fTractionCurveLateral peak**: "peak … = fTractionCurveLateral / 2" — [GTAMODS](https://gtamods.com/wiki/Handling.meta); also "Peak grip sits at half" — [swisser.dev](https://ai.swisser.dev/fivem-handling-editor/fields/fTractionCurveMax); "will tend to stay below half of this value" — [EDDLM](https://eddlm.github.io/Handling-Tools/handling); vs. "full angular range… maximum angle… before the wheels start to slide" — [GTACARS](https://gtacars.net/gta5/glossary); vs. "Optimal slip angle before grip decreases" with real-world 6–9.3° figures — [IKT-NOTES](https://github.com/ikt32/GTAVHandlingInfo/blob/master/notes.json). Myth: "value is angle / 10 (1.0 is 10°)" — [Reddit r/GTAV_Mods](https://www.reddit.com/r/GTAV_Mods/comments/334to7/gta_5_handling_file/) — contradicted by the deg→rad conversion of the raw value (22.5 → 0.3927 rad) — [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)
- **fSteeringLock**: DWNSTR says it "multiplies the game's calculation… Values between 0.1 - 0.2 will simulate a long wheelbase… around 0.75 and above will turn extremely fast" — [DWNSTR](https://docs.dwnstr.com/data-files/handling) — contradicted: it is degrees (~40), converted deg→rad in memory — [GTAMODS](https://gtamods.com/wiki/Handling.meta); [IKT-CONV](https://github.com/ikt32/GTAVHandlingEditor/blob/master/RTHandlingEditor/HandlingConversion.cpp)

### Inferences
- For a Roblox re-implementation, prefer the memory-verified conversions (IKT-CONV) and disassembly-derived formulas (GTACARS-DF), then GTACARS/IKT tester formulas; treat GTAMODS free-text and DWNSTR (older V4D3R tutorial, partly GTA IV-era wording) as lowest confidence.
- For the traction curve, a defensible implementation is: grip rises linearly from 0 to fTractionCurveMax as |slip| goes 0→peak, then lerps to fTractionCurveMin using the stored `1/(Max−Min)`; expose the peak position (0.5× vs 1.0× fTractionCurveLateral) as a tunable since the community disagrees.
